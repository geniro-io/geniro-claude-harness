# EXP-003: guard-test completeness check in tests criteria

- **Module:** review
- **Status:** draft
- **Failure pattern:** guard-test assertion gaps. Deterministic misses in both
  trials of the legacy dev baseline: `real-1` gt-1 (every test pins the
  feature flag to OFF, so the ON branch — routing PII-bearing drafts to real
  recipients — has zero coverage) and `real-2` gt-3 (an authz guard test
  asserts the returned total but never that the critical element is included,
  so a regression excluding exactly that element still passes). Both are
  class `test-gap`: the test EXISTS and looks relevant, but cannot fail for
  the regression it guards.
- **Change (ONE thing):** one bullet added to tests-criteria §8 Coverage
  Gaps — for every guard test, name a concrete regression that would still
  pass the test as written; a guard that cannot catch its regression is HIGH.
- **Prediction:** unlocks real-1 gt-1 and/or real-2 gt-3 → recall_must +1..2
  items; noise up by ≤0.3/task (risk: speculative test-gap findings on
  planted/negative tasks).
- **Success gate:** Δrecall_must CI > 0 on dev, `planted-neg-1` still passes
  (negative task must stay clean); holdout + second family confirm.
