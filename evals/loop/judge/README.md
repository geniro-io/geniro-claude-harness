# Judge layer

The judge grades one trial's findings against the task rubric. Its prompt is
generated by `loop_lib.py judgeprompt` (reference-guided, deterministic shuffle,
strict-match instructions, an explicit no-guess escape, anti-verbosity line) and
its verdict contract is:

```json
{"matches": [{"gt_id": "...", "finding_ids": ["F1"], "reason": "..."}],
 "residue": [{"finding_id": "...", "bucket": "plausible-real|noise|nitpick", "reason": "..."}]}
```

Rules the prompt encodes (sources: MT-Bench judge-bias findings, Anthropic
model-graded-eval guidance):

- **Reference-guided, binary per item** — per-defect match verdicts, never a
  holistic 1–5 score.
- **Blind** — the judge never learns which variant produced the findings;
  finding order is shuffled deterministically.
- **Different family** — primary judge is Claude subagents (executor is a
  Cursor CLI model); the paid fallback is another family again.
- **Escape hatch** — "cannot tell" goes to residue as noise with reason
  "unclear match", never a guessed match.

## Calibration (`calibration/`)

A judge is trusted only against human labels. Cycle (scoped Critique
Shadowing):

1. After a scored run, sample judged trials: `kappa.py sample <run-dir> -n 20`
   writes `calibration/pending-<stamp>.jsonl` — one row per (gt_id × trial)
   match verdict plus each residue bucket.
2. The human labels each row (`human`: same field shape as `judge`) with a
   one-line critique where they disagree.
3. `kappa.py score calibration/<file>.jsonl` prints Cohen's κ, raw agreement,
   and TPR/TNR for the match verdicts. κ < 0.6 or a repeated critique theme →
   fix the judge prompt in `loop_lib.py`, re-shadow a fresh batch.

Re-shadow after ANY judge-prompt change and after executor/judge model swaps.
Labeled batches stay committed — they are the judge's regression suite (with
the judge's `reason` prose stripped: it quotes finding text from private
source repos).

## Standing result — `labeled-2026-08-10.jsonl` (n=10, champion run)

κ **0.72**, agreement 0.80, TNR 1.0 (3 match rows, all `missed`, all
confirmed — no false matches, so no inflated recall; TPR undefined at this n).
The judge is trusted above the κ ≥ 0.6 bar; recall figures in the EXP files
stand.

Both disagreements are the same theme: the judge bucketed an unmatched
finding `plausible-real` where the human said `nitpick` (test-coverage claims
for analytics events, and a test-env credential-hygiene note). The judge
over-credits low-stakes findings. Consequence is bounded — the split affects
only the `noise` vs `nitpick` reporting split, never `recall_must` or
`noise_strict`, and it errs toward flattering the reviewer's residue. Fix
only if a future experiment turns on the plausible-real column; then sharpen
the `nitpick` definition in `loop_lib.py judgeprompt` and re-shadow.
