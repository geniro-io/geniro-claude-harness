# EXP-014: can a harder fixture de-saturate audit-instructions recall?

- **Module:** audit-instructions
- **Status:** landed — **refuted**. Recall stayed 1.0; the floor re-measured at
  1.92/task and replaces EXP-011's 2.6.
- **Failure pattern:** EXP-011 found recall at 1.0 on every positive task, so
  its MDE of 0 was a ceiling rather than sensitivity — no recall variant could
  ever be promoted, because there was nowhere for a gain to land.
- **Change (ONE thing):** the benchmark, not the skill. Nine new must-find
  items, every one deliberately multi-hop, spread across all five positive
  tasks plus one new task. Champion unchanged on both arms.
- **Prediction:** recall drops below 1.0 on at least two tasks, opening
  headroom a later variant can compete for.
- **Success gate:** any positive task scoring under 1.0 in either arm.

## What was planted

Each item was chosen to survive the check a one-hop reviewer already passes:

| task | item | why it should be hard |
|---|---|---|
| planted-1 | `db:migrate` resolves in package.json; its body applies one hard-coded file, and the SQL has no `IF NOT EXISTS` | the command name exists — the lie is in the body and one file further |
| planted-2 | `alwaysApply: true` declared beside `globs` | the rule loads; the glob is silently decorative |
| planted-3 | secrets sent to `.env.local` "because it is gitignored"; `.gitignore` lists `.env` | a dotenv pattern is present, just not this one |
| planted-4 | CLAUDE.md → AGENTS.md → Cursor rule → nothing | each hop is individually valid |
| planted-5 | handler package that is a deprecation shim; ruff hook under `stages: [manual]`; `globs: app/**.py`; root absolute contradicted by a nested CLAUDE.md; hand-added section in a generated file | existence checks pass on all five |

## Runs

| stage | run dir | verdict |
|---|---|---|
| A-vs-A, de-saturated dev set, 2 trials/arm, panel of 3 | `runs/scratch/ai2-a` vs `ai2-b` | recall unchanged at 1.0; noise floor 1.92/task |

**recall_must: 1.0 on every positive task, every trial, both arms — 20/20, zero
misses.** Mean delta 0, 0W/0L/5T, CI95 [0, 0], MDE 0. Identical to EXP-011 on a
benchmark built specifically to break it.

**noise:** mean delta 1.92/task, CI95 [-0.17, 4.92], MDE 2.54, recorded as the
module's floor. Down from 2.6 (1 trial, single judge); the second trial and the
panel each took part of it. One task carries most of what is left — planted-4
ran 12/12 noise findings in arm A against 2/4 in arm B.

**Cost:** $4.33 executor (120 calls), 72 judge calls / 2.30 Mtok unpriced.

## Decision

**Refuted, and the refutation generalizes.** Nine items designed to need a
second hop cost the executor nothing. The reason is that "multi-hop" is not
what makes a hop expensive: a small synthetic tree is entirely in context, so
another file read is free. The hops that defeat a reviewer in a real repository
are expensive because of scale — thousands of files, unclear ownership, no
history — and a hand-built fixture cannot express scale. Fixture *difficulty*
and fixture *size* are different variables, and only the second one was ever
the constraint.

So the recall axis on this module is closed the way EXP-002/003/005/006 closed
the review module's content axis: not "we failed to find the gain" but "the
measurement cannot see one, and we now know why". Do not spend another round on
cleverer plants.

**What remains open.** Two levers this stand already supports and this
experiment did not touch: staging a *real* repository (`repo_url` /
`repo_alias`), and screening a different executor tier. Either changes the
variable that actually binds. Precision/noise also stays open — that axis has a
floor now, and it is 1.92.

**A second result, unplanned.** The A-vs-A exposed both modules' negative
controls as mis-specified — the champion returned identical findings on them in
every trial of both arms, which is the signature of a broken fixture rather than
a noisy reviewer. `plugin-neg-1` carried a genuine CRITICAL guard bypass. Both
are repaired; see the two `NOTES.md` files. The audit-plugin floor of 2.75 was
measured over that broken task and is now marked an upper bound in its
`target.json` rather than trusted or deleted — a contaminated task inflates the
band, which makes verdicts insensitive rather than wrong.
