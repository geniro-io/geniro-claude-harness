# EXP-007: A-vs-A — does the spec-check stand measure signal or noise?

- **Module:** spec-check
- **Status:** landed (stand calibration, no skill change)
- **Failure pattern:** n/a — this is the mandatory first run on a new benchmark
  (DESIGN.md §A-vs-A). Champion against champion must come back a tie; the CI
  width is the noise floor every later verdict on this module is read against.
- **Change (ONE thing):** none. Both arms are `variants/champion`, same prompts,
  fresh executor subagents per arm (no cache replay between them).
- **Prediction:** exact recall tie; some noise spread, since the flagged set
  beyond the rubric is where run-to-run variance lives.
- **Success gate:** recall delta indistinguishable from zero. A significant
  difference would mean the stand cannot separate a real effect from run noise
  and must not be used until it can.

## Setup

- Executor: Claude subagents (`adapters/claude-subagent.md` §Executor protocol).
  This is the faithful choice, not the cheap one — production spec-challenge
  spawns Claude verifiers, so a composer-2.5 sweep would measure a configuration
  nobody runs. Free on subscription; no spend approval was needed or sought.
- Judges: 12 blind Claude subagents, one per trial, each reading only its own
  `judge-prompt.txt`.
- Benchmark: 6 dev (5 positive, 11 must-find items + 1 negative), rubric v1.

## Decision

The stand separates signal from noise on recall and is usable. Two bounds to
carry into every later verdict on this module:

1. **The recall MDE of 0 is not infinite sensitivity — it is coarseness.** Four
   of five positive tasks scored 1.0 in both arms, so the per-task deltas had
   nowhere to land. The suite is near the saturation DESIGN.md §6 warns about,
   and a recall win on it would have to come from the one task that is not
   saturated. Treat recall here as a floor check, not a fine instrument, until
   the benchmark grows harder tasks.
2. **The noise floor is 0.33 findings/task.** A future variant moving noise by
   less than that is reporting run-to-run variance.

**Real miss, reproducible in both arms:** `planted-5` `gt-2` — the spec calls the
`legacy-ledger-read` flag "now-unused" while the config it cites shows it enabled
at 100%. Both arms caught the sibling claim (the rollout is at 5%, not 100%) and
neither caught this one. A defect adjacent to a caught defect, in the same file,
went unflagged twice — the first error-analysis lead this module produced, and
the natural target for EXP-008.
