# EXP-006: authored repo-rules slot — does it earn its tokens? (ablation)

- **Module:** review
- **Status:** rejected
- **Failure pattern / motivation:** three dev tasks (real-2, real-11,
  real-13) carry rule-based ground truth and inject the source repo's
  authored rule files (~40KB) into EVERY facet prompt via
  `include_repo_rules`. The slot's value was assumed, never measured; the one
  legacy single-trial probe unlocked nothing. If the slot buys nothing, it is
  paid dead weight on every real-task cell and should be removed.
- **Change (ONE thing):** task-level ablation — copies of the three tasks
  with `include_repo_rules` stripped; reviewer content unchanged. Incumbent
  (rules ON) arm is the standing cached champion.
- **Prediction:** rules-ON beats rules-OFF on recall_all / recall_weighted of
  the rule-citing items (real-11's zod/api-rule findings, real-13's
  domain-events HIGH); recall_must unchanged (those misses are test-gap
  class). If OFF ≈ ON across the board, the slot is dead weight → drop it.
- **Success gate:** diagnostic, n=3 — no promotion machinery. Decides: keep
  slot / drop slot / expand slot to more tasks. Read per-item matches, not
  just aggregates, before deciding.

## Decision

REJECTED (slot buys nothing measurable) 2026-08-10, diagnostic n=3, t1.
First pass had a confound — screen_facets excludes conventions, the facet
that would cite rules — caught and fixed: both arms re-ran WITH the
conventions facet. Result unchanged: matched rule-based items 1/1/0 (ON) vs
1/1/0 (OFF), recall_weighted differences inside single-trial variance, noise
tied. The injected ~40KB of authored rules does not convert into the
specific accepted rule-based findings for this executor.

Action: keep `include_repo_rules` on the three tasks for production
FIDELITY (the shipped skill does load repo rules), but the "expand rules to
more tasks" backlog item is dead — no measured recall payoff to chase. The
per-cell cost of the slot is negligible (~10K tokens), so fidelity wins over
removal.
