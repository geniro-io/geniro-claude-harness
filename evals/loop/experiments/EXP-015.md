- **Module:** recon (new) — `/geniro:implement` Phase 1 Step 7, the
  knowledge-retrieval + codebase-explorer spawn pair.
- **Status:** landed — tie recorded (stand calibration, no skill change)
- **Failure pattern:** n/a — the mandatory first run on a new benchmark
  (DESIGN.md §A-vs-A). Champion against champion must tie; the CI width is the
  noise floor every later verdict on this module is read against.
- **Change (ONE thing):** none. Both arms are `variants/champion` at the shipped
  tiers — knowledge facet on `sonnet` (the frontmatter carve-out), explorer
  facet on the session tier — with fresh executor subagents per arm.
- **Prediction:** exact recall tie. Noise spread likelier on the knowledge half,
  where a report can surface a real store entry the rubric did not plant.
- **Success gate:** recall delta indistinguishable from zero.

## What this module measures

Phase 1 Step 7 hands the orchestrator everything it will act on before the first
edit: which past learning governs the task, which handoff is open on this branch,
which files the change touches, what already exists to reuse, which rules
constrain it. The rubric's items are those things. `recall_must` reads "did Phase 1
hand the orchestrator what it needed"; `noise_strict` reads "did it assert
something that is not there".

The two directions do NOT cost the same, and this module scores them accordingly.
An unmatched review finding claims a defect exists; an unmatched recon item only
says a file may be relevant — usually true, and cheap when wrong. So
`negative_pass_expr` drops the `plausible_real` clause the other modules carry.

## Setup

- **Executor: Claude subagents** through the `mock` transport, so the driver
  assembles the real prompts and `collect-subagent-results.sh` wraps the output.
  The faithful choice, not the cheap one: these two agents run at their
  frontmatter tiers inside a live session, so a composer-2.5 sweep would measure
  a configuration nobody runs. `spec.json.adapter` records the transport;
  `model` carries the brain (`claude-kr-sonnet+ce-opus`).
- **Judges:** blind Claude subagents, one per trial, each reading only its own
  `judge-prompt.txt`.
- **Benchmark:** 6 dev — 5 positive (34 must-find items) + 1 negative. All
  synthetic; no task is mined from a real repository, so nothing here needs
  anonymizing. Item classes: past learning, handoff, prior plan, likely-touched
  file, exemplar, rule match, REUSE-AS-IS / EXTEND / NO-ANALOGUE, change_scope,
  and two absence-scored traps (a deprecated store entry, two non-matching rule
  globs).
- **New machinery this module required**, all with defaults that leave the other
  three modules byte-identical: a `recon-items` parser reading the agents' OWN
  output schemas rather than a block shape the stand imposes; per-module
  `judge_framing` in `target.json`; `polarity: "absence"` rubric items; and a
  `dot-geniro/` → `.geniro/` rename at stage time, because the
  `enforce-state-helper` hook matches `.geniro/<tier>/` anywhere in a path and
  cannot tell benchmark fixture data from this repo's own state. The hook was
  left exactly as strict as it is.

## The first pass was measuring three broken things

The run came back with a recall CI that excluded zero on the combined noise axis
and two tasks moving in opposite directions. None of it was the agents.

**1. Absence-scored items were unrepresentable in the scorer.** `cmd_metrics`
counted a ground-truth item as found when its match list was non-empty, so an
item meaning "the report must NOT claim this" scored as a MISS exactly when the
report behaved correctly. Worse, it was unstable: from identical instructions one
arm's judge attached the finding that named the trap as excluded, the other left
the list empty — same correct behavior, opposite scores. Both of the first pass's
recall differences came from this. Fixed with a first-class `polarity: "absence"`
item type: an explicit judge rule and an inverted found-test.

**2. `planted-5` gt-3 asserted something false about its own tree.** The item
required `src/lib/spread.ts` to be classed EXTEND because it "does not compose
with a growing delay without a change of signature". It composed fine —
`spread(cadenceMs: number)` is assignable to `shape: (delayMs, attempt) => number`
in TypeScript, since a function of lower arity satisfies a higher-arity type.
BOTH arms classified it REUSE-AS-IS, both cited the assignability, and both
explicitly flagged the codebase-map row as contradicted by the tree. They were
right and the rubric was wrong. `spread` now takes an options object, which
genuinely cannot be passed as `shape`, restoring the intended EXTEND.

**3. Every line number in two fixture codebase maps was wrong** — `throttle`
cited at :24 (actually :20), `requireTenant` :12 (:10), `bumpCounter` :7 (:6),
`attemptSeries` :26 (:20). Arm B called this out unprompted. Corrected; EXP-009's
lesson stands — a task that misdescribes its own tree teaches the executor to
distrust the task text.

The contested-must detector earned its keep: it flagged `planted-5` gt-3 in arm
A, which is what sent the transcript read to the defect.

## Two bounds to carry into every later verdict on this module

1. **The recall MDE is 0.050 at 1 trial × 5 positive tasks.** An effect smaller
   than that is invisible here, whatever the point estimate says.
2. **The champion scores 1.0 on every positive task in a clean arm, so this
   benchmark detects HARM well and improvement barely.** That is a real limit —
   the same one EXP-009 and EXP-010 recorded for partition — but it happens to
   fit the two hypotheses queued behind it, EXP-016 and EXP-017, which are both
   cost-reduction proposals whose whole question is whether quality HOLDS.

Do not read the combined `noise` axis on this module: it is dominated by the
nitpick bucket, which swung 1.33 findings/task between identical arms. Use
`noise_strict`.
