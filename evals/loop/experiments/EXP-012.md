# EXP-012: can the codebase-explorer run at `sonnet` instead of the session tier?

- **Module:** recon
- **Status:** landed — tie recorded, **no skill change** (see §Decision)
- **Failure pattern:** not a failure — a cost question. The Phase 1 pair is
  asymmetric: `knowledge-retrieval-agent` declares `model: sonnet` (a documented
  mechanical-gather carve-out, `model-tiering.md` category 3) while
  `codebase-explorer-agent` declares `model: inherit` with `maxTurns: 80`, so on
  an Opus session the explorer is the expensive half of the pair by a wide
  margin. `model-tiering.md` puts it explicitly in the stay-inherit list on the
  grounds that "output quality scales with orchestrator intelligence". That
  claim had never been measured.
- **Change (ONE thing):** the explorer facet runs at `sonnet`. Nothing else
  moves — same preamble, same criteria, same benchmark, same rubrics.
- **Prediction (written before the run):** `recall_must` holds on the mechanical
  items (likely-touched files, exemplars, rule globs) and drops on the two
  multi-hop reuse items — `planted-1` gt-1 (`throttle()`, which shares no
  vocabulary with the spec and is reachable only through the sibling route that
  imports it) and `planted-5` gt-1/gt-2 (`attemptSeries` plus its `shape` hook).
  Those are the items where "reasoning about an unfamiliar tree" is doing the
  work. Also predicted: `change_scope` disagreements, since that is a judgment
  call rather than a lookup.
- **Success gate:** no `recall_must` loss beyond the EXP-011 MDE of 0.050.

## Setup

Paired against the EXP-011 champion arm (`runs/scratch/ava-a`), which scored
`recall_must` 1.0 on all five positive tasks.

**The knowledge half is held literally constant, not resampled.** The candidate
run reuses the champion arm's `result-knowledge.txt` files verbatim, because that
facet's configuration is identical in both arms — same prompt, same `sonnet`
tier. Resampling it would inject variance into a variable the experiment does not
manipulate. The contrast is therefore exactly one thing: the explorer's tier.

## What actually changed

Not recall — terseness. On `planted-1` the champion emitted 3 likely-touched
files, 5 reuse-inventory rows, 2 rule rows and a Spec-Referenced Files section;
the sonnet run emitted 1, 3, 1 and dropped that section. Every ground-truth item
was in the smaller set. The dropped rows were real and correctly cited; they were
simply not load-bearing.

One of those drops is arguably an improvement. The champion listed
`.claude/rules/web-ui.md` under Relevant Rules in order to say it does not match;
the sonnet run left it out. The agent's own contract calls its output "a signal
funnel", and the shorter report is the one that reads like one.

## Decision — tie recorded, and the skill is NOT changed

The measurement says: at this benchmark's resolution, moving the explorer to
`sonnet` costs no ground truth and cuts report volume a quarter. It does not say
the tier is safe to pin, and this experiment is not a promotion, for three
reasons that are worth writing down rather than re-deriving later.

1. **The benchmark cannot see improvement, and can barely see harm.** The
   champion scores 1.0 on `recall_must` AND `recall_all` on every positive task,
   so the recall MDE is 0 — that is coarseness, not precision. A real degradation
   smaller than one whole item on one task is invisible here. EXP-011 already
   recorded this bound; EXP-012 is its first consumer.
2. **Six synthetic trees are not the population.** Every task here is authored,
   small, and self-consistent. The explorer's job on a real repository is
   scoping a spec against a tree with dead code, three competing helpers, and a
   stale codebase map. That is precisely where tier plausibly matters and where
   this suite has no coverage.
3. **The doctrine question is not a measurement question.** `model-tiering.md`
   keeps judgment-grade spawns on `inherit` because *the user chose their tier*
   and pinning a researcher cheaper is the documented paternalism anti-pattern.
   A tie on six tasks does not settle that; it removes one argument (that the
   explorer visibly needs the bigger model) without touching the other.

What this DOES settle is the premise: the explorer is not obviously
tier-sensitive, so "the explorer must stay on inherit because its quality scales
with the model" is now an unsupported claim rather than an assumed one.

**Named next step, if this is pursued:** the honest promotion path is not a
second screen on these six tasks — they are saturated. It is harvesting real
Phase 1 misses from production runs into tasks the champion actually fails
(EXP-010's recipe for partition), then re-running this contrast against them.
Until then the tier stays `inherit`.
