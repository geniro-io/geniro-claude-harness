# EXP-010: de-saturate the partition benchmark

- **Module:** partition
- **Status:** landed — benchmark change only, no artifact change
- **Failure pattern:** not an artifact failure — a stand failure. EXP-009's
  A-vs-A returned `recall_must` 1.0 on every positive task in both arms, so the
  per-task deltas had nowhere to land and the recall MDE of 0 is coarseness, not
  sensitivity. The module can currently prove a variant did no harm and cannot
  prove one helped.
- **Change (ONE thing):** the benchmark, not the artifact. `variants/champion`
  is byte-identical to EXP-009. Two edits, both to the task set:
  1. **Rubric v2 on three dev tasks**, promoting couplings that EXP-009's runs
     surfaced and that were then verified against the tree by hand.
  2. **Two new dev tasks** (`planted-5`, `planted-6`) built around coupling
     classes no existing task carries.
- **Prediction (written before the run):** `recall_must` drops below 1.0 on at
  least one positive task. Per task, in descending order of expected difficulty:
  - `planted-6` gt-1 — **expected miss.** Establishing it requires deriving the
    file set of a module that does not exist yet: the receipt todo's not-yet-
    written code must call the function the currency todo is re-signing. Every
    coupling in the benchmark so far is discoverable by reading a file that
    exists.
  - `planted-5` gt-1 / gt-2 — **expected miss.** The champion preamble's list of
    "where false independence actually lives" names barrels, types, registries,
    config, ordering and duplicate helpers. It names no test artifact. Both
    couplings here are test-side: a golden output file and the fixture that
    feeds it, and neither todo mentions tests.
  - `real-2` gt-4 — **coin flip.** One of the two EXP-009 arms found it and the
    other did not, from identical prompts.
  - `planted-1` gt-3, `real-1` gt-3 — **expected hit.** Both arms already stated
    these; they were only invisible to the scorer because they arrived as prose
    inside another block.
- **Success gate:** at least one positive task below 1.0. If every task scores
  1.0 again, the benchmark is still saturated and the correct next move is
  another round of harder tasks — not a variant experiment, which would be
  measuring a metric with no room to move.

## What changed in the task set

**Rubric v2 — promoted from EXP-009 residue, each verified against the tree:**

| task | new item | class | must_find | why it is honest ground truth |
|---|---|---|---|---|
| `planted-1` | gt-3 | module-private-state | yes | `const ledger: Invoice[] = [];` is never exported, so the summary helper has to be authored into the same file the PDF renderer is added to |
| `real-1` | gt-3 | closed-vocabulary | yes | the kind union is a 2-member const object and its override map is an exhaustive `Record` over it, so widening the union without a key there is a compile error |
| `real-1` | gt-4 | construction-site | **no** | the metrics service is injection-only (a shared metrics package) and the adapter is not a Nest provider, so a timing sink is wired at the module's adapter factories — but an implementation reusing the already-injected logger touches no module file, so it scores in `recall_all` only |
| `real-2` | gt-3 | god-container | yes | the transcript screen container is the sole holder of the transcript state and render loop the export and virtualization todos both write |
| `real-2` | gt-4 | god-container | yes | the same file holds the folder state and `chooseFolder`; `folder-select.tsx` is presentational and never calls the bridge itself |

`real-1` gt-4 is deliberately the only `must_find: false` item in the module. It
exists so a correct-but-optional coupling stops landing in residue, where it
inflates `plausible_real` and reads as a rubric gap.

`real-1`'s rubric is at `version: 3`, not 2: v2 asserted that the timing sink's
metrics-service route did not exist, from a grep scoped to one app alone.
It exists in a shared package. The claim was corrected before any run was
scored against v2, and the bump keeps the version rule mechanical.

**Two new dev tasks:**

- `planted-5` — Python reporting CLI. Three of four todos change the rendered
  table, and the suite's only assertion is a byte-for-byte comparison against one
  committed golden file, which the fixed-width layout re-pads whole. Two of them
  additionally need a new field in the single fixture the golden is generated
  from. Columns are discovered by directory scan, so there is deliberately no
  registry to give the coupling away.
- `planted-6` — TypeScript billing service. The currency todo re-signs the one
  money renderer and sweeps its call sites; the receipt todo writes a module that
  does not exist yet and must call that renderer, per the convention stated in
  its docstring and demonstrated by all three existing call sites. Second item:
  the retry todo edits one of the very call sites the sweep rewrites — the
  champion preamble's own carve-out says a mechanical hub sweep is not coupled
  "by that fact alone", which is exactly where it can go wrong.

predicted to be safe.

| `planted-5` gt-1 / gt-2 — expected miss (no test artifact in the preamble's list) | **both found**; it emitted all three golden-file pairs and derived the fixture-input coupling unprompted |

The lesson is about the predictor, not the model: reasoning about which couplings
are hard for this instruction produced a worse ranking than measuring did. Both
new task classes, built specifically as blind spots, were answered on the first
pass.

## The failure both misses share

Neither miss is a coupling the run failed to see. Both are a SECOND shared write
site for a todo pair whose FIRST site the run found and reported:

- `planted-1` — reported the barrel for todo-2+todo-4, did not add that the same
  pair also collides inside `invoice.ts` over the private ledger.
- `real-1` — reported the registry constructor for todo-1+todo-2 and folded
  the closed union into the same block's prose, but never reached the providers array
  for that pair, though it cited that array twice for todo-3.

The champion's output contract says "One block per coupled PAIR of todos — not
per group, and not per file", with a single `**Shared:**` line per block. The
rubric scores per write site. So a pair with three shared files has one block and
one slot to name them in, and the surplus sites land in `**Why:**` prose or are
dropped — EXP-009 recorded the prose variant of exactly this. Two readings, and
they are separable by experiment: the format suppresses enumeration, or detection
genuinely stops at the first hit.

**Named next experiment — EXP-011, one change:** make the shared-file slot a list
so a pair can carry every write site that couples it. Predicted effect:
`recall_must` recovers on `planted-1` and `real-1` with `noise_strict` unmoved.
If it does not move, the cause was detection and the format was innocent.

## The blind spot the metrics do not cover

`parse_partition_couplings` reads `### [COUPLED]` blocks and nothing else, so the
`## Partition Summary` — which todos go to a delegate and which stay inline — is
unscored. That is the half of Phase 2 that produces the harm: a missed coupling
only costs something once the two todos are actually handed to different agents.

Across the six positive runs the summary was filled in two incompatible ways:
`planted-2` and `planted-6` bundled the coupled todos into a numbered `Group`
with `Inline (coupled): none`, while `planted-1`, `planted-3`, `planted-5` and
`real-2` routed them to `Inline (coupled)`. The shipped skill is not ambiguous —
`phase-2-implement.md` says a coupled todo "joins the single coupled group
instead, edited inline". The champion preamble never states that rule, so this is
a fidelity gap in the stand rather than evidence the skill misbehaves. Bundling
coupled todos into one delegate is safe against write collisions; it is wrong
against the skill's rule that coupled work needs the orchestrator's judgment.

Scoring the routing decision would need a second parser and rubric axis. Not
attempted here — recorded so no later verdict on this module is read as covering
it.
