# EXP-020: does re-keying the intentional-refactor guard to diff-visible evidence cost the conventions dimension anything?

- **Module:** review
- **Status:** screening
- **Framing — this is a NON-INFERIORITY check, not a win hunt.** The change already
  shipped, as a correctness fix rather than a recall bet: the old text ordered the
  reviewer to "check the PR description for refactor intent", and the `conventions`
  dimension never receives the PR description — so the guard could not fire at all. The
  question worth money is not "does it help" but "does the replacement suppress
  legitimate modal findings". A tie PASSES.
- **Failure pattern:** an instruction with no input. `conventions` is absent from the
  PR-metadata dimension set, so the old bullet was dead on arrival. Its false-positive
  class is real, though: on a deliberate cross-cutting refactor the old pattern is still
  the modal one, so every site of the new convention reads as a violation.
- **Change (ONE thing):** `criteria/conventions-criteria.md` §Common false positives
  item 3 only — verified as the sole diff against the champion snapshot. Old text keyed
  the guard to the PR description; new text keys it to the changed-file set (one
  transformation repeated across unrelated modules, replacing rather than coexisting),
  and narrows the instruction to "flag only a changed file that breaks from it".
- **Prediction:** **exact tie on both axes.** No committed dev task carries a genuine
  intentional-cross-cutting-refactor with modal violations to weigh, so the changed
  branch is unlikely to fire at all. `planted-neg-1` (behavior-preserving refactor) has
  been holding its zero-noise gate in prior experiments, so noise there is already at the
  floor and has no room to improve. The one real risk being measured is the opposite
  direction: "flag only a changed file that breaks from it" is a suppression clause, and
  it could cost conventions a legitimate modal finding on `planted-2` / `planted-5` /
  `smoke-1`, which do carry house rules.
- **Success gate (non-inferiority):** noise_strict not worse than champion on any task,
  AND no conventions ground-truth item present in the champion arm missing from the
  candidate arm. A tie on both clears it. A noise INCREASE or a lost item fails and the
  shipped text gets revisited.
- **Why a tie here is informative when a tie usually is not:** the alternative hypothesis
  is not "the change is inert" — it is "the change removed dead text and broke nothing",
  which is exactly what a tie establishes for a correctness fix. Read this against
  EXP-002/003/005/006, where a tie meant the opposite (a hoped-for gain did not
  materialise); the asymmetry is in what was predicted, not in the statistics.

## Setup

- Executor: `composer-2.5`, the designed screening tier. Probe-measured at **$0.0486 per
  call, $0.22/Mtok** on this workload shape.
- Facet: `conventions` ONLY — and note it is deliberately NOT in the module's
  `screen_facets` subset (`bugs`, `security`, `tests`, `regressions`), so this run
  overrides that. A default screen would never have exercised the changed file.
- Tasks: all 7 committed dev tasks, not only the 2 that plausibly exercise the guard.
  The extra 5 are the regression surface — at $0.05/call they are free, and a suppression
  clause's cost shows up where house rules exist, not where refactors do.
- Arms: champion (holds the OLD text — verified, no `sync-champion.sh` run, which would
  have overwritten the baseline with the shipped text and destroyed the comparison) vs
  `variants/exp020-conventions-guard` (overrides that one criteria file with the shipped
  text; every other file inherits).
- Trials: 2 (screening minimum — single-trial effects exaggerate).
- Estimated spend: ~$1.36 (7 tasks x 2 arms x 2 trials = 28 calls).

**Gate check.** `noise_strict` is 0 in both arms on every task — not worse anywhere. No
systematic ground-truth loss: `smoke-1` trial-1 lost one match (champion 2/3 → candidate
1/3) and `planted-2` trial-1 gained one (0/3 → 1/3), netting the exact recall tie; both
sit inside the stand's ~1.1 findings/task noise floor. Gate passed.

**The prediction was wrong in the favourable direction, and that is the finding.** An
exact tie on both axes was predicted. Recall tied exactly; noise did not — it halved.
The mechanism is visible in one per-trial cell: on `planted-4` trial-1 the CHAMPION (old
text) emitted a noise finding and the candidate emitted none. So the dead instruction was
not merely inert. Pointing the reviewer at a source it never receives left it with NO
modal-suppression signal at all, and re-keying the guard to the changed-file set supplies
one. That reframes the change from "removed dead text" to "restored a suppression signal
that had never been able to fire".

**Do not overclaim it.** The CI includes 0 and the point estimate sits exactly at the
MDE, on 7 tasks x 2 trials with a single-arm judge. This is "not worse, plausibly
better", not a win, and it does not license a promotion claim — the change was already
shipped on correctness grounds.

**Cost recorded:** +36.7% input tokens on the conventions facet. Telling the reviewer to
look for one transformation repeated across the changed-file set makes it read more of
that set. Cheap here (this facet is one of ten) but it is a real increase, not free.

**Reusable stand note:** `conventions` is absent from `screen_facets`, so no default
screen exercises it. Any future conventions-criteria experiment must pass
`--facets conventions` explicitly or it measures nothing.

## Decision

**Landed, non-inferiority confirmed 2026-08-12.** No skill change from this run — the
text screened is the text already on `main` (`35d31b0d`). Champion snapshot deliberately
NOT synced during the run so the old text stayed the baseline; sync it on the next
`sync-champion.sh --module review` so subsequent experiments compare against the shipped
text.
