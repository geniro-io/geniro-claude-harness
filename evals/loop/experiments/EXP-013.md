# EXP-013: does one merged recon agent match the knowledge + explorer pair?

- **Module:** recon
- **Status:** landed — tie recorded. No skill change. The escalation this
  screen originally owed was resolved by fixing the RULE, not by waiving it for
  this run (see §Escalation).
- **Failure pattern:** not a failure — a topology question. Phase 1 Step 7 spawns
  two agents in one response. Their reads are disjoint (memory layers vs. source
  tree) and both reports drain into the same Step 8 consumer, so the split is a
  design choice, not a necessity. One agent would mean one spawn, one context,
  one drain.
- **Change (ONE thing):** `variants/exp-013-merged` replaces the two facets with
  a single `recon` facet carrying BOTH agent contracts, and a preamble that says
  to execute both Workflows and emit both Output Schemas. Criteria files are the
  shipped agent bodies, byte-identical to champion.
- **Prediction (written before the run):** recall holds on the explorer half and
  drops on the knowledge half. The memory sweep is four mechanical steps over
  JSONL and handoff files; the code reconnaissance is the interesting problem,
  and a single agent budgeting its own turns should starve the boring half —
  most likely the `Prior Plans` step (`planted-2` gt-1) and the deprecated-entry
  filter (`planted-3` gt-6), both of which need the agent to keep reading after
  it already has a plausible answer.
- **Success gate:** no `recall_must` loss beyond the EXP-011 MDE of 0.050.

## Escalation — the rule was wrong, and it was fixed rather than waived

As written when this screen ran, DESIGN.md's sequential-trials rule stopped at
one trial only when the recall delta was an exact tie AND `|Δnoise|` was under
the A-vs-A noise-of-noise. Recall was an exact tie; `|Δnoise|` was 1.67 against a
band of 1.50, so the rule demanded a second trial.

The trigger was spurious, and not only for this run. `noise` is
`noise_strict + nitpick`, and nitpick is the judge's classification of findings
that matched no ground-truth item — it moves with judge taste, not with executor
behavior. EXP-011 had already measured that axis swinging 1.33 findings/task
between two IDENTICAL champion arms. A gate on it escalates on judge variance and
tells you nothing about the variant, which is exactly what happened here:
`noise_strict` was 0 in both arms on every task.

Waiving the check for this experiment would have been the thing pre-registration
exists to prevent. Instead the rule itself was corrected — it now reads
`|Δnoise_strict|` against the module's own measured band, for every future
experiment, and the borrowed 1.1/task constant it used to name (review's number,
never re-derived) is gone. Under the corrected rule this screen stops at one
trial: Δrecall_must = 0 exactly, Δnoise_strict = 0.

**Tie recorded.** Still not a promotion — nothing about this experiment argues
for merging, per §"What the 1-trial screen does and does not support" below.

## What the 1-trial screen does and does not support

It supports: merging does not silently drop the memory half. That was the
concrete risk, it was predicted, and it did not happen on any of six tasks.

It does not support merging. Three things stand against it, none of which this
benchmark measures:

1. **Wall-clock.** The pair runs concurrently in one assistant response; a merged
   agent runs their work in series. This suite has no timing axis (the subagent
   path is deliberately unmetered), so the cost the merge actually incurs is the
   one number not on the table.
2. **The tier collapse.** The two agents are on purpose at different tiers —
   `sonnet` for the mechanical sweep, session tier for the reconnaissance. One
   agent has one tier, so merging forces either the memory sweep up to the
   session tier or the reconnaissance down. Both are worse trades than the split,
   and note this cuts directly against EXP-012: taken together, the two results
   say the pair should stay split and the interesting lever is the explorer's
   tier, not the agent count.
3. **The output contract has two consumers.** Step 8 drains `.kr-out.md` and
   `.ce-out.md` separately, and the store-empty gate at Step 7 skips the
   knowledge slot alone when the memory store is empty. A merged agent has no
   skippable half, so on a fresh repository it would do the sweep that the gate
   exists to avoid.

**Decision: no change.** The topology stays two agents. The measurement removed
the quality objection to merging and left the three structural ones standing.
